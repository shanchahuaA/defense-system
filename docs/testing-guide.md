# 毕业答辩管理系统 - 功能测试指南

按这份指南可以手工把每个角色的主要流程走一遍。所有命令都假设当前目录是仓库根目录。

## 一、启动项目

### 1. 启动后端

```bash
cd backend
# 先按 ../README.md「配置」一节准备好数据库连接（环境变量或 application.yml）
mvn spring-boot:run
```

后端运行在 `http://localhost:8080`。上传目录落在 `backend/uploads/`（配置项是相对 JVM 工作目录解析的 `${user.dir}/uploads`，从这里启动即 `backend/uploads`）。

### 2. 启动前端

另开一个终端：

```bash
cd frontend
npm install
npm run dev
```

前端运行在 `http://localhost:5173`，开发服务器把 `/api` 与 `/uploads` 都代理到 `8080`。

## 三、功能测试步骤

### 测试1：个人签名上传

1. 登录任意教师账号
2. 点击左侧菜单「个人中心」→「个人签名」
3. 点击上传区域，选择一张签名图片（前端只放行 PNG / JPG，且不超过 2MB）
4. 点击「确认上传」
5. **预期结果**：页面显示"上传成功"，签名图片在预览区显示

### 测试2：AI配置（超级管理员）

1. 登录 admin 账号
2. 点击左侧菜单「系统配置」→「AI配置」
3. 填写通义千问 API Key（如没有可跳过）
4. 点击「测试连接」按钮
5. 编辑论文/设计评语模板
6. 点击「保存配置」
7. **预期结果**：显示"配置保存成功"

### 测试3：模板管理（超级管理员）

1. 登录 admin 账号
2. 点击左侧菜单「系统配置」→「模板管理」
3. 在任意模板类型行点击「上传」
4. 选择一个 .docx 文件（可先用 `docs/templates/` 下那份）
5. **预期结果**：显示"上传成功"，状态变为"已上传"

### 测试4：我指导的学生（教师）

**前置条件**：需先在「学生管理」中创建学生并分配指导教师

1. 登录教师账号
2. 点击左侧菜单「我指导的学生」
3. 点击学生行的「编辑」按钮
4. 修改论文题目、摘要信息
5. 点击「保存」
6. **预期结果**：信息更新成功

**测试指导成绩填写**：

1. 点击「指导成绩」列的「填写」按钮
2. 输入 0-100 的成绩
3. 点击「提交」
4. **预期结果**：成绩显示在列表中

**测试选择评阅人**：

1. 点击某学生行的「选评阅人」按钮
2. 在下拉列表中选择一位教师
3. 点击「确定」
4. **预期结果**：评阅人分配成功

### 测试5：大组答辩评分（教师）

**前置条件**：

- 需要有答辩小组
- 小组内学生需要有小组答辩成绩（groupAvgScore）

1. 登录教师账号
2. 点击左侧菜单「大组答辩评分」
3. 查看大组答辩学生列表（每个小组的第一名）
4. 点击某学生的「评分」按钮
5. 输入 0-100 的成绩
6. 点击「提交评分」
7. **预期结果**：评分保存成功，「我的评分」列显示分数

### 测试6：答辩记录（教师）

1. 登录教师账号
2. 点击左侧菜单「答辩记录」
3. 点击某学生的「填写」按钮
4. 填写答辩日期、地点、问题记录、答题情况、评价
5. 点击「保存」
6. **预期结果**：状态变为"已填写"

### 测试7：文档导出（教师）—— 当前不可用

1. 登录教师账号
2. 点击左侧菜单「文档导出」
3. 选择一个答辩小组
4. 点击某学生行的「导出文档」按钮，任选一种文档类型
5. **实际结果**：只弹出一句提示，不会产生文件。原因见 README「已知问题与后续计划」第 1 条

## 四、测试数据准备

数据库结构与测试数据都在 `docs/design/` 下，按顺序执行：

```bash
mysql -u root -p < docs/design/init.sql               # 建库建表 + 评分指标 + 超管账号
mysql -u root -p < docs/design/test_data.sql          # 5 个学院 / 10 个教师 / 10 个学生
mysql -u root -p < docs/design/test_scoring_data.sql  # 答辩分组与小组评分
```

`full_test_data.sql` 是另一套更小的英文数据集，用于验证导出流程；它开头会 `TRUNCATE ai_config`，跑之前注意。

## 五、常见问题排查

### 页面显示 404

- 检查前端路由是否正确、是否已登录

### 接口返回 403

- 检查登录状态是否过期
- 确认当前用户角色是否有权限访问该功能

### 上传失败

- 签名图在前端就被拦下：只放行 PNG / JPG、不超过 2MB（`frontend/src/views/profile/Signature.vue`）
- 服务端另有一个 10MB 的 multipart 上限（`application-example.yml` 的 `spring.servlet.multipart`）。**后端自己不校验类型和 2MB**——绕过前端直接调接口可以传更大的文件，这是一处已知的服务端校验缺失
- 检查 `backend/uploads/` 目录是否有写入权限

### 应用启动就报错

- 报 `Access denied for user 'root'@'localhost' (using password: NO)` → 数据库口令没配或填错，见 README「配置」
- 报 `Could not resolve placeholder 'JWT_SECRET'` → JWT 密钥没配，见 README「配置」
- 报 `Table 'defense_management.xxx' doesn't exist` → 还没执行 `init.sql`（`ddl-auto` 是 `validate`，不会自动建表）
